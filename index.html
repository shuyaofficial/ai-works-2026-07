01 / HOW I LEARN

私の学習方法。仮想環境を、AIと一緒に回す。

VS Codeを操作卓にして、設計書、コンフィグ、仮想配線、試験ログを同じ場所で扱います。AIはContainerlabの中にいるのではなく、共有ファイルとSSH／ターミナルを通じて、一緒に設計・構築・切り分けを行います。

LAYER 01

Apple Silicon Mac

手元のMacが学習環境の入口。arm64ネイティブのOSSと、x86エミュレーションのCisco IOLを使い分けます。

LAYER 02

VS Code

Remote-SSHでclab@orbへ接続。srl-labsのContainerlab拡張で構成表示、Deploy、Attachを行います。

LAYER 03

OrbStack VM

Ubuntu VM上でDockerとContainerlabを実行。Macと同じパスでファイルを共有し、編集と実行をつなぎます。

LAYER 04

Virtual Network

Cisco IOL、FRR、SR Linux、Linuxコンテナを仮想リンクで接続し、CLIとパケットの挙動を確かめます。

LEARNING LOOP

設計を、試験結果まで閉じる

  1. 学びたい技術と合格条件を決める
  2. 要件・基本設計・IPアドレス表を作る
  3. トポロジーとstartup-configへ変換する
  4. Containerlabへデプロイする
  5. ping・経路・認証・ログを試験する
  6. AIと原因の仮説を分解して切り分ける
  7. 設計書と構築ログへ戻し、再試験する

WORKSPACE

同じ画面で扱うもの

  • .clab.yml
  • .cfg
  • 設計書.md
  • 試験結果.md
人が持つこと

学習目標、設計判断、変更の許可、合格判定。AIの提案をそのまま正解にしません。

AIが支援すること

設計案、設定部材、試験観点、ログ比較、原因仮説、ドキュメント更新。

学習の成果は「動いた構成」だけではなく、なぜ失敗し、何を直したかまで残すことです。

02 / WHY ZERO TRUST

高価で見えにくいなら、分解して確かめる。

商用製品を置き換えるのではなく、製品の中で何が起きているのかを、自分の手で理解したかった。
このラボの境界

個人学習ではライセンスや検証テナントへのアクセスが壁になります。そこでAIと機能を分解し、OSS中心＋L2/L3はCisco IOLの仮想環境で、主要な制御モデルを学習再現しました。

N1 / NAC

接続前に、端末を識別する。

VERIFIED
  • 802.1X EAP認証に成功
  • VLAN10 FreeRADIUSから動的割当
  • 未認証端末 通信不能を確認
  • PARTIAL VLAN99自動隔離・CoAは未確認
N4 / MICROSEG

通してよい通信だけを残す。

VERIFIED
  • Inter-VLAN HTTP 80許可／SSH 22拒否
  • Same VLAN nftables適用後、損失0%→100%
  • Cilium 別ラボで未許可L4遮断・/admin 403
N3 / NDR

境界の内側も、観測する。

VERIFIED
  • Suricata east-west SYNスキャンを検知
  • Loki 統合ラボで277行を取り込み
  • Grafana health OK
  • MANUAL 検知から隔離の投入は手動
N2 / SDP-ZTNA

サービスを、直接見せない。

VERIFIED
  • Overlay OpenZiti経由はHTTP 200
  • Direct サーバ直接経路はHTTP 000
  • Model connectorの張り出し経由だけで到達

04 / NETWORK-TOOLS

設計から切り分けまで、7つのネットワークツール。

Macを操作端末に、ネットワーク作業の流れを支援する独立Webアプリ群です。6つは決定論的な実務ツール、7つ目だけがAnthropic APIを使うAIトリアージです。

DESIGN
01 / :8601

マクロ作成

VLAN、IF、OSPF、BGP、拡張ACLのテンプレートからCisco IOSコマンドを生成。

技術と制約

Jinja2 sandbox。ACL各行の完全な構文検証と複数VLANのtrunk指定は今後の課題です。

説明書 ↗
04 / :8604

FWポリシー管理

ベンダー中立ルール、パケットマッチ、shadow・重複・包含分析、ASA／FortiGate生成。

技術と制約

IPv4・単一CIDR中心。分析0件は安全性の保証ではありません。

説明書 ↗
EXECUTE
06 / :8606 / FLAGSHIP

Mac向けネットワークターミナル

最大20タブでlocal shell、SSH、Telnet、Serialを扱い、自動ログ、スニペット、プロンプト待ち、複数行paste確認を備えます。MacにないTelnetのIAC交渉も実装しました。

技術と制約

xterm.js同梱、WebSocket、PTY、macOSの/usr/bin/ssh、pyserial。高度なTelnet交渉には未対応です。

説明書 ↗
VERIFY
02 / :8602

Ping・障害試験

複数宛先のRTT・loss、断復旧イベント、停止時Traceroute、試験レポート、CSV。

技術と制約

SSE＋Canvas。macOSのping／tracerouteを使用し、IPv4のみ対応します。

説明書 ↗
EVIDENCE
03 / :8603

事後ログ取得・管理

複数機器の作業前後show出力をSSH収集し、案件単位で保存・検索・差分比較。

技術と制約

Netmiko優先、Paramiko fallback、SQLite＋plaintext logs。主要5系統のNOSを選択できます。

説明書 ↗
05 / :8605

コンフィグ管理

running-configをSSH取得または貼り付けでスナップショット化し、版間diffと横断検索。

技術と制約

SQLite FTS5。利用できない環境ではLIKE検索へ自動フォールバックします。

説明書 ↗
TRIAGE
07 / :8607 / AI

障害トリアージAI

症状、show出力、ログから最大5件の原因仮説を確信度・OSIレイヤー・根拠付きで提示。確認結果を加えて再分析できます。

技術と制約

Anthropic SDK＋SSE。入力証拠は外部APIへ送信されます。機器を操作せず、読み取り専用コマンドを提案します。

学習環境

Mac → VS Code → OrbStack → Containerlab → 試験 → AI切り分けのループ。

社員端末

802.1X認証後、VLAN10へ割り当て、ACLを通って業務サーバへ接続。

未認証端末

認証に失敗し、core-swで業務通信を停止。VLAN99自動隔離は未確認。

感染端末

Suricataがスキャンを検知し、Loki／Grafanaへ集約。隔離は手動。

リモート

OpenZiti overlay経由はHTTP 200、サーバ直接経路はHTTP 000。
